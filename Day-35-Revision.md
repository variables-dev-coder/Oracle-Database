# Complete Revision

## 1. Oracle Database Architecture

An Oracle environment has two major parts:

```text
ORACLE
|
+-- INSTANCE
|   |
|   +-- SGA
|   |
|   +-- Background Processes
|
+-- DATABASE
    |
    +-- Datafiles
    |
    +-- Control Files
    |
    +-- Online Redo Log Files
```

---

## 2. SGA

SGA stands for **System Global Area**.

SGA is shared memory used by the Oracle Instance.

### Main Components

```text
SGA
|
+-- Database Buffer Cache
|
+-- Shared Pool
|
+-- Redo Log Buffer
```

### Database Buffer Cache

Stores copies of database blocks in memory.

```text
Datafile
   |
   v
Buffer Cache
   |
   v
Database Block
```

### Shared Pool

Contains important SQL, PL/SQL and database metadata information.

```text
Shared Pool
|
+-- Library Cache
|
+-- Data Dictionary Cache
```

### Redo Log Buffer

Stores redo information generated by database changes.

```text
Database Change
      |
      v
Redo Log Buffer
```

---

## 3. Background Processes

Important Oracle background processes are:

```text
DBWR
LGWR
CKPT
SMON
PMON
```

### DBWR

DBWR means **Database Writer**.

Writes appropriate dirty blocks from the Buffer Cache to datafiles.

```text
Buffer Cache
     |
     | Dirty Blocks
     v
    DBWR
     |
     v
 Datafiles
```

### LGWR

LGWR means **Log Writer**.

Writes redo from the Redo Log Buffer to Online Redo Log Files.

```text
Redo Log Buffer
      |
      v
     LGWR
      |
      v
Online Redo Logs
```

### CKPT

CKPT means **Checkpoint Process**.

Coordinates checkpoint-related work.

### SMON

SMON means **System Monitor**.

Important responsibility:

```text
Instance Recovery
```

### PMON

PMON means **Process Monitor**.

Performs cleanup related to failed user/server processes.

---

## 4. Physical Database Files

The main physical files are:

```text
DATABASE
|
+-- Datafiles
+-- Control Files
+-- Online Redo Log Files
```

### Datafiles

Store database data.

### Control Files

Store important information about the database structure.

Examples:

- Database name
- Datafile information
- Redo log information
- Checkpoint information

### Online Redo Log Files

Store redo information written by LGWR.

---

## 5. Oracle Storage Structure

Oracle storage is organized as:

```text
DATABASE
   |
   v
TABLESPACE
   |
   v
DATAFILE
   |
   v
SEGMENT
   |
   v
EXTENT
   |
   v
BLOCK
```

### Tablespace

A logical storage container.

### Datafile

A physical file belonging to a tablespace.

### Segment

Storage allocated for a database object.

Examples:

- Table segment
- Index segment
- Undo segment

### Extent

A collection of blocks allocated to a segment.

### Block

The basic unit of Oracle database storage.

## 6. Users and Schemas

### User

A database account.

```sql
CREATE USER munna
IDENTIFIED BY password;
```

### Schema

A logical collection of objects owned by a user.

Example:

```text
MUNNA
|
+-- EMPLOYEE
+-- DEPARTMENT
+-- EMP_VIEW
+-- EMP_SEQ
+-- PROCEDURES
+-- FUNCTIONS
```

Memory:

```text
USER   = Account
SCHEMA = Objects owned by the user
```

## 7. Privileges and Roles

### Privilege

A permission to perform an operation.

Two major categories:

```text
PRIVILEGES
|
+-- System Privileges
|
+-- Object Privileges
```

Example:

```sql
GRANT CREATE SESSION TO munna;
```

### Role

A collection of privileges.

```text
ROLE
|
+-- SELECT
+-- INSERT
+-- UPDATE
+-- DELETE
```

Example:

```sql
GRANT developer_role TO munna;
```

## 8. Profiles

A profile controls password and resource-related policies.

Examples:

- Failed login attempts
- Password lifetime
- Password reuse
- Password lock time
- Resource limits

Example:

```sql
CREATE PROFILE developer_profile
LIMIT
FAILED_LOGIN_ATTEMPTS 5
PASSWORD_LIFE_TIME 90;
```

Assign profile:

```sql
ALTER USER munna
PROFILE developer_profile;
```

Memory:

```text
PROFILE = USER POLICY
```

## 9. DML

DML means **Data Manipulation Language**.

Main commands:

```text
INSERT
UPDATE
DELETE
```

Example:

```sql
INSERT INTO employee
VALUES (1, 'Munna', 50000);
```

```sql
UPDATE employee
SET salary = 60000
WHERE id = 1;
```

```sql
DELETE FROM employee
WHERE id = 1;
```

---

## 10. DDL

DDL means **Data Definition Language**.

Main commands:

```text
CREATE
ALTER
DROP
TRUNCATE
```

Example:

```sql
CREATE TABLE employee (
    id NUMBER,
    name VARCHAR2(100),
    salary NUMBER
);
```

DDL changes database structure.

---

## 11. Transactions

A transaction is a logical unit of work.

Example:

```sql
UPDATE employee
SET salary = salary + 5000
WHERE id = 10;
```

The transaction can be completed with:

```text
COMMIT
```

or undone with:

```text
ROLLBACK
```

---

## 12. COMMIT

COMMIT makes eligible changes in the current transaction permanent.

Example:

```sql
UPDATE employee
SET salary = 60000
WHERE id = 10;

COMMIT;
```

For a commit, Oracle ensures the required redo is written to stable online redo storage.

```text
DML
 |
 v
Redo Generated
 |
 v
Redo Log Buffer
 |
 v
LGWR
 |
 v
Online Redo Log
 |
 v
Commit Acknowledged
```

---

## 13. ROLLBACK

ROLLBACK undoes eligible uncommitted changes.

Example:

```sql
UPDATE employee
SET salary = 100000
WHERE id = 10;

ROLLBACK;
```

---

## 14. UNDO

UNDO stores information Oracle uses for:

- Rolling back changes
- Providing read consistency

```text
DML
 |
 v
Previous Version Information
 |
 v
UNDO
```

Memory:

```text
UNDO
|
+-- ROLLBACK
|
+-- READ CONSISTENCY
```

---

## 15. REDO

REDO is information generated by Oracle to support recovery.

REDO is different from the actual data block.

```text
Database Change
      |
      +------------------+
      |                  |
      v                  v
Data Block             REDO
      |                  |
      v                  v
Buffer Cache       Redo Log Buffer
```

Two different purposes:

```text
DATA BLOCK
    -> Current database information

REDO
    -> Information used during recovery
```

---

## 16. Redo Log Groups and Members

Online redo logs are organized into groups.

Example:

```text
GROUP 1
|
+-- Member 1
+-- Member 2

GROUP 2
|
+-- Member 1
+-- Member 2

GROUP 3
|
+-- Member 1
+-- Member 2
```

Multiple members in a group provide redundancy.

This is called **Redo Log Multiplexing**.

---

## 17. Log Switch

When Oracle switches from the current redo log group to another group, it performs a log switch.

```text
GROUP 1
   |
   v
LOG SWITCH
   |
   v
GROUP 2
   |
   v
LOG SWITCH
   |
   v
GROUP 3
```

---

## 18. Checkpoint

A checkpoint is a synchronization point used by Oracle for recovery-related processing.

During checkpoint processing, appropriate dirty blocks are written to datafiles.

```text
Checkpoint
    |
    +-- Checkpoint information
    |
    +-- DBWR writes appropriate dirty blocks
```

Remember:

```text
CKPT
    -> Checkpoint coordination

DBWR
    -> Writes dirty blocks
```

---

## 19. SCN

SCN means **System Change Number**.

SCN is a logical number used by Oracle to represent database change and ordering information.

Think of it as:

```text
Oracle's Logical Clock
```

It is not a normal date/time value.

SCN is important for:

- Consistency
- Recovery
- Redo
- Database synchronization
- Data Guard

Example:

```text
Change A -> SCN 100
Change B -> SCN 101
Change C -> SCN 102
```

---

## 20. ARCHIVELOG

In ARCHIVELOG mode, Oracle preserves redo from online redo logs by archiving it before the relevant online redo can be reused.

```text
Online Redo Log
      |
      | Log Switch
      v
    ARCn
      |
      v
Archived Redo Log
```

ARCHIVELOG is important for:

- Media recovery
- Point-in-time recovery
- Backup and recovery
- Data Guard

---

## 21. TEMP Tablespace

TEMP is used for temporary operations.

Examples:

- Large SORT operations
- HASH operations
- Temporary SQL processing

Simplified:

```text
SQL Operation
      |
      v
    Memory
      |
      | Not enough memory
      v
TEMP Tablespace
```

Memory:

```text
UNDO -> Rollback + Read Consistency

TEMP -> Temporary Operations
```

## 22. CDB and PDB

Oracle Multitenant architecture uses containers.

Example:

```text
CDB
|
+-- CDB$ROOT
|
+-- PDB$SEED
|
+-- XEPDB1
```

### CDB

CDB means:

```text
Container Database
```

### PDB

PDB means:

```text
Pluggable Database
```

PDBs contain application data and objects.

Check current container:

```sql
SHOW CON_NAME;
```

Show PDBs:

```sql
SHOW PDBS;
```

Change container:

```sql
ALTER SESSION SET CONTAINER = XEPDB1;
```

---

## 23. Data Guard

Oracle Data Guard uses a primary database and standby database(s) to provide high availability and disaster recovery capabilities.

Basic architecture:

```text
PRIMARY DATABASE
       |
       | REDO TRANSPORT
       v
STANDBY DATABASE
       |
       v
   REDO APPLY
```

The primary generates redo.

The standby receives and applies redo.

---

## 24. Primary Database

The Primary Database is the main database where normal production transactions occur.

Example:

```text
APPLICATION
     |
     v
PRIMARY DATABASE
     |
     +-- INSERT
     +-- UPDATE
     +-- DELETE
```

These changes generate redo.

---

## 25. Standby Database

A Standby Database is maintained from redo received from the primary.

```text
PRIMARY
   |
   | Redo Transport
   v
STANDBY
   |
   | Redo Apply
   v
STANDBY DATABASE
```

## 27. RAC

RAC means:

```text
Real Application Clusters
```

RAC allows multiple Oracle instances to work with the same database.

```text
                  DATABASE
                     |
          +----------+----------+
          |                     |
        NODE 1                NODE 2
          |                     |
      INSTANCE 1           INSTANCE 2
```

Each instance has its own SGA and background processes.

---

## 28. RAC Node

A Node is a server participating in the RAC cluster.

```text
RAC CLUSTER
|
+-- Node 1
|
+-- Node 2
```

Each node can run an Oracle RAC instance.

---

## 29. RAC Instance

Each RAC instance has its own memory and background processes.

```text
NODE 1
 |
 +-- INSTANCE 1
      |
      +-- SGA
      +-- DBWR
      +-- LGWR
      +-- Other Processes


NODE 2
 |
 +-- INSTANCE 2
      |
      +-- SGA
      +-- DBWR
      +-- LGWR
      +-- Other Processes
```

The instances work with the same database.

---

## 30. RAC Redo Thread

Each RAC instance has its own redo thread.

```text
INSTANCE 1
     |
     +-- THREAD 1


INSTANCE 2
     |
     +-- THREAD 2
```

Memory:

```text
Instance 1 -> Thread 1

Instance 2 -> Thread 2
```

A redo thread identifies the redo stream associated with a RAC instance.

# 36. Important Differences

## Instance vs Database

```text
INSTANCE
-> Running Oracle environment
-> SGA + Background Processes

DATABASE
-> Physical database files
```

## DBWR vs LGWR

```text
DBWR
-> Dirty database blocks
-> Datafiles

LGWR
-> Redo information
-> Online Redo Logs
```

## REDO vs UNDO

```text
REDO
-> Recovery

UNDO
-> Rollback
-> Read Consistency
```

## Tablespace vs Datafile

```text
TABLESPACE
-> Logical

DATAFILE
-> Physical
```

## User vs Schema

```text
USER
-> Account

SCHEMA
-> Objects owned by the user
```

## Privilege vs Role

```text
PRIVILEGE
-> Permission

ROLE
-> Collection of permissions
```

## Online Redo vs Archived Redo

```text
ONLINE REDO
-> Current redo logs

ARCHIVED REDO
-> Preserved redo from online redo logs
```

## RAC vs Data Guard

```text
RAC
-> Multiple Oracle instances
-> Same database
-> Cluster architecture

DATA GUARD
-> Primary database
-> Standby database
-> Redo transport and apply
```

# 37. Interview Questions

## Q1. What is an Oracle Instance?

An Oracle Instance is the running Oracle environment consisting mainly of SGA and background processes.

## Q2. What is an Oracle Database?

An Oracle Database is a collection of physical files that stores database information.

## Q3. What is SGA?

SGA is shared memory used by an Oracle Instance.

## Q4. What are the important SGA components?

```text
Database Buffer Cache
Shared Pool
Redo Log Buffer
```

## Q5. What does DBWR do?

DBWR writes appropriate dirty blocks from the Buffer Cache to datafiles.

## Q6. What does LGWR do?

LGWR writes redo from the Redo Log Buffer to Online Redo Log Files.

## Q7. What is a tablespace?

A tablespace is a logical storage container.

## Q8. What is a datafile?

A datafile is a physical file that belongs to a tablespace.

## Q9. Can one tablespace have multiple datafiles?

Yes.

```text
TABLESPACE
|
+-- DATAFILE 1
+-- DATAFILE 2
+-- DATAFILE 3
```

## Q10. What is a segment?

A segment is storage allocated for a database object.

## Q11. What is an extent?

An extent is a collection of blocks allocated to a segment.

## Q12. What is an Oracle block?

An Oracle block is the basic unit of database storage.

## Q13. What is a schema?

A schema is the logical collection of objects owned by a user.

## Q14. What is a role?

A role is a collection of privileges.

## Q15. What is a profile?

A profile defines password and resource-related policies.

## Q16. What is REDO?

REDO is information generated by Oracle to support recovery.

## Q17. What is UNDO?

UNDO stores information used for rollback and read consistency.

## Q18. What is LGWR?

LGWR is the Log Writer process that writes redo to Online Redo Log Files.

## Q19. What is a log switch?

A log switch occurs when Oracle changes from one online redo log group to another.

## Q20. What is a checkpoint?

A checkpoint is a synchronization point used for database recovery-related processing.

## Q21. What is SCN?

SCN stands for System Change Number and represents logical database change/order information.

## Q22. What is ARCHIVELOG?

ARCHIVELOG mode preserves redo by archiving online redo logs before they are reused.

## Q23. What is Data Guard?

Data Guard maintains standby database(s) from redo generated by a primary database.

## Q24. What is RAC?

RAC allows multiple Oracle instances to work with the same database.

## Q25. What is a RAC node?

A node is a server participating in a RAC cluster.

## Q26. What is a RAC redo thread?

## Q27. What is CDB?

CDB means Container Database.

## Q28. What is PDB?
